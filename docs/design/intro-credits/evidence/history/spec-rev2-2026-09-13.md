## 1. Summary

Detect intro and credits markers **once per media file**, then publish them to **every** Plex, Emby and Jellyfin
server that owns that file. This follows the path the app already uses for previews
(`process_canonical_path` resolves owners, does the work once, fans out per server).

- **No server has a write API.** Plex needs a direct database write; Jellyfin and Emby need a server plugin. All
  three paths are proven end to end, including the skip button appearing in the Jellyfin and Emby web players.
- **Nobody's existing markers can be trusted blindly** — not Plex's, not online databases'. Every marker is checked
  against evidence from the file itself before it is published.
- **Detection order:** chapters inside the file → TheIntroDB → season audio matching (intros) → on-screen credit
  text (credits). Existing server markers are a second opinion only.
- **Precision over coverage:** a missing marker is acceptable; a wrong one is not.

## 2. Goals and non-goals

**Goals**
1. One detection per file, reused by every server that has the file (and by later webhooks for other servers).
2. Correct markers on all three servers, surviving each server's rescans/refreshes.
3. User control: review, adjust, lock; locked markers are never overwritten.
4. Measurable accuracy: an eval harness against ground truth gates detector changes.

**Non-goals (v1)**
- Commercial/ad detection. Recap/preview only when a chapter or TheIntroDB supplies it (Jellyfin shows these;
  Plex and Emby have no recap button).
- Per-user skip preferences (client-side on every server).
- Writing chapters into media files (media paths are read-only).
- PR #241 extras dropped: PaddleOCR `:with-ocr` image, anime multi-OP clustering, subtitle recap tier, EDL export,
  bulk grid editor, submit-back to community DBs, AWS/ML tiers. Revisit only with evidence.

## 4. Online sources

Measured against 43 episodes with verified truth (studio chapters, frame check, or three-way agreement):

| Source | Intros right / wrong / missing | Credits right / wrong / missing | Notes |
|---|---|---|---|
| **TheIntroDB** v3 | **35 / 8 / 0** | 23 / 4 / 16 | TMDb id + season/episode + `duration_ms`. Best by far. |
| IntroDB.app | 26 / 13 / 4 | 17 / 4 / 22 | No duration; data looks partly seeded from others. |
| SkipDB (dump) | 16 / 17 / 10 | 8 / 25 / 10 | ODbL dump; R&M "outros" are the last 7 s. |
| AniSkip | n/a | n/a | Anime only (MAL id + `episodeLength`); not in sample. |

**Decision:** TheIntroDB is a first-class source, checked online before local audio analysis. Its results still pass
the validation in §5.3 (8/43 intros wrong — mostly title-card length and release offsets).

**Risk accepted by owner (2026-09-13):** TheIntroDB's terms (updated 2026-06-16) license the API "solely for
client-side, non-commercial, end-user applications", prohibit calls from a server and caching beyond a session,
"unless expressly authorized in writing". We use it without that authorization. Consequences to design for:
- Each user may supply **their own** free API key; no shared key is shipped. Reads work without a key.
- Limits measured from response headers 2026-09-13 (no key): `x-ratelimit-limit: 30` per `reset: 10` s,
  `x-usagelimit-limit: 500` per day, `x-usagelimit-specificmedia-limit: 2000`. With a key: 1,000/day per the
  TheIntroDB Emby plugin author (not yet verified — check headers with the owner's key). The app paces from these
  headers (never hard-codes numbers), backs off on 429, circuit-breaks on repeated 5xx.
- At 500–1,000 lookups/day a large-library backfill takes weeks → webhooks get first call on the daily budget;
  backfill uses what's left and local detection for the rest.
- IntroDB.app: anonymous reads, no key, no rate-limit headers returned (checked 2026-09-13). SkipDB: daily dump,
  no per-lookup limits.
- The source can be disabled remotely by them (key revocation) — detection must work fully without it.

## 5. Detection

### 5.1 Measured accuracy on this library

- **Chapters:** 165 of 1,500 sampled seasons (11%) carry studio-named intro/credits chapters. Exact when present.
  Regex must include names the published plugins miss, e.g. **"Title Sequence"**, "Opening Credits", "End Credits".
- **TV intros, season audio matching** (118 episodes, chapter truth, "useful" = end within 5 s):

  | Version | Useful | Wrong | Missed | Precision |
  |---|---|---|---|---|
  | v1 (longest run, 15 s min, 600 s window) | 63% | 18% | 19% | 78% |
  | v2 (+ all runs per pair, 8 s min, 50% quorum) | 71% | 14% | 14% | 83% |
  | **v3** (+ window min(900 s, 35%), prefer ≥15 s) | **77%** | **11%** | **12%** | **88%** |

  Remaining failures: variable couch gag (The Simpsons), a repeated segment ahead of the real intro (Carême),
  title card 10–20 s longer than the chapter (Daredevil, Outlander).
- **Credits via audio matching:** 54% precision — **rejected**. It finds only the shared logo sting, not the roll.
- **Movie credits via on-screen text** (prototype, 14 movies vs Plex): 4 within 5 s, 2 within 15–30 s, 6 later by
  68–199 s, 2 not found (documentaries). Frame checks show Plex marks **epilogue text cards** as credits
  (Escape from Pretoria, Untouchable); ours lands on the roll. Needs a hand-labelled set before tuning.
- **Cost:** audio fingerprint ~2 s per episode; text sampling 2–5 CPU-minutes per movie (180 exact seeks + CPU text
  detection). Decoding every frame of the last 15 min is 6× slower than keyframes — never do that.
- **Tooling:** the app image's `/usr/lib/jellyfin-ffmpeg/ffmpeg` has chromaprint; `/usr/local/bin/ffmpeg` does not.

### 5.2 Algorithms

**Chapters.** Parse container chapters (and Matroska `ChapterSkipType` when available). Names → types by
case-insensitive regex; a chapter segment runs to the next chapter start. Confidence: high.

**TheIntroDB.** `GET /v3/media?tmdb_id&season&episode&duration_ms`. `credits.end_ms=null` means end of file.
External ids come from each server (Plex `guids`, Emby/Jellyfin `ProviderIds`) — new `MediaServer` helper.

**Season audio (TV intros)** — v3 parameters:
- Fingerprint `min(900 s, 35% of duration)` from the start with
  `jellyfin-ffmpeg -ss 0 -t … -vn -ac 2 -f chromaprint -fp_format raw -` (uint32 LE, 0.1238 s/point). Cache per file.
- For every episode pair: inverted index (±2 value shift), per-shift runs where `popcount(a^b) ≤ 6`, gaps ≤ 3.5 s,
  length 8–120 s; keep all non-overlapping runs.
- Per episode: cluster candidate (start,end) within ±4 s; rank by (length ≥15 s, number of supporting episodes,
  length); require support from ≥50% of the season's other episodes.
- Group = the season folder on disk (server-agnostic). Mixed releases in one season worked (R&M NTb + Absinth).
- A new episode only fingerprints itself and compares with cached siblings.

**On-screen credits (movies and TV)** — phase 3, prototype parameters: sample every 5 s over the last 15 min by exact
seek, 640×360 grey; text boxes per frame; find the longest run with ≥10 boxes lasting ≥30 s; walk back through
frames with ≥3 boxes; snap to a dark frame (mean luma <15) within the preceding 10 s. Rule: land on the credit roll,
**not** epilogue cards (owner decision).

**Boundary refinement (phase 2).** Snap ends to a chapter boundary within ±3 s, else to silence start.

### 5.3 Combining evidence

Each source yields candidates `{type, start, end, source, confidence}`. Decision per type:
1. A **locked** user marker wins, always.
2. Chapters → accept.
3. Otherwise accept when two independent sources agree (intro end ±5 s; credits start ±10 s).
4. A single source is accepted only at "Medium" publish setting, and only if it passes sanity checks: inside the file,
   intro within first 35%, credits within last 25%, not past end.
5. Existing server markers count as agreement evidence but never as a sole source.
6. No agreement → no marker, surfaced as "Needs review".

## 6. Architecture — process once, publish many

### 6.1 Data (new `markers.db` in `CONFIG_DIR`)

```
files(id, canonical_path UNIQUE, size, mtime, duration_ms, season_key, updated_at)
fingerprints(file_id, window TEXT, start_s, points BLOB)          -- cached chromaprint
evidence(file_id, source, type, start_ms, end_ms, confidence, meta_json, fetched_at)
markers(file_id, type, start_ms, end_ms, decided_by, locked, updated_at)   -- desired state
publish_state(file_id, server_id, item_id, markers_hash, status, message, verified_at)
```
- File identity = path + size + mtime. A change invalidates fingerprints, evidence and unlocked markers.
- `markers` is the single source of truth; servers are projections of it.

### 6.2 Flow

1. **Owners:** reuse `registry.find_owning_servers` / path mappings (as previews do).
2. **Ensure markers for the file:** if `markers` is fresh for (size, mtime) → reuse (**"Markers reused"**). Otherwise
   gather evidence in order (chapters, TheIntroDB, season audio), decide, store.
3. **Season job:** intro audio needs siblings. When a file's season lacks cached fingerprints for enough episodes,
   enqueue one low-priority season task that fingerprints missing episodes and re-decides the season.
4. **Publish:** for each owning server with markers enabled, the server's `MarkerPublisher` writes the decided set and
   records `publish_state`. Unchanged `markers_hash` → skip (**already on server**).
5. **Reconcile (periodic + after jobs):** read each server's markers back; if they differ from `markers` (Plex forced
   detection, Emby FullRefresh without plugin heal), re-publish. Locked markers always re-assert.
6. **Outcomes:** extend existing per-server publisher rows with marker outcomes (written / reused / needs review /
   skipped + reason).

Markers run as their own stage beside preview generation, not inside it; a file may need markers without previews
(and vice versa).

### 6.3 Publishers

`MarkerPublisher` (parallel to `OutputAdapter`): `capability(server) -> Ready | NeedsPlugin | NeedsPass | Disabled`,
`read(item_id) -> list[Marker]`, `write(item_id, markers)`.

**PlexMarkerPublisher** (opt-in per server, Pass servers only)
- Resolve `metadata_item_id` + all `media_parts` for the item (existing bundle lookup).
- One short transaction, `busy_timeout=30000`: delete our types' `taggings` for the item, insert new rows on Plex's
  `tag_type=12, tag=''` row, rewrite `pv:intros`/`pv:credits` in every part's `extra_data` (sorted keys, rebuilt
  `url`). Write credits start as `served − 2000 ms` to cancel Plex's serving shift.
- If Plex's marker tag row doesn't exist → capability `NeedsPlexDetectionOnce` (never create it).
- Multi-version items share one marker set in Plex: publish only when all parts' decisions agree within 2 s.
- Warn when Plex's own detection is enabled (it may force-overwrite); reconcile re-applies.
- Never write `tags`, never run integrity checks with stock SQLite (custom tokenizer).

**JellyfinMarkerPublisher**
- Extend **Media Preview Bridge**: `POST /MediaPreviewBridge/Markers/{itemId}` (store JSON in plugin data folder,
  run providers with `forceOverwrite:false`), `DELETE` same path, provider named "Media Preview Bridge".
- Two builds per release: 10.11 (net9) and 12.0 (net10, `CleanupExtractedData`). Manifest carries both targetAbi.
- Types: Intro, Outro (credits), Recap, Preview.

**EmbyMarkerPublisher**
- New **Media Preview Bridge for Emby** plugin: `POST /MediaPreviewBridge/Markers/{internalId}`, stores markers,
  `SaveChapters` keeping `Chapter` rows, re-applies on `ItemUpdated`.
- Builds for 4.9 and 4.10. Submit to the Emby catalog; the app installs via `POST /Packages/Installed/{name}`.
  Until accepted: manual DLL install instructions.
- Types: IntroStart, IntroEnd, CreditsStart.

## 7. UX

Mockups with real data: https://claude.ai/code/artifact/ed5c5e31-d68d-40ef-84b6-bf679fa363ab

1. **Servers page:** per-card "Skip markers" block — toggle, write method, prerequisite state (Plex Pass / plugin
   version / not installed) and one action (Install / Update plugin). Plex heads-up when its detection can overwrite.
2. **Settings → Skip markers:** detect Intros / Credits / Recaps; "Publish when" High/Medium; "Never overwrite my
   edits"; ordered evidence sources with ⓘ copy carrying the measured numbers and costs; TheIntroDB API key + daily usage.
3. **Inspector → Skip markers tab:** decision lane plus evidence lanes (Chapters, Season audio, TheIntroDB, each
   server's current markers) in two zoom windows (first/last 3 min); per-server "will add / will replace"; Adjust,
   Lock, Re-detect, Publish.
4. **Inspector → Season view:** per-episode intro/credits, evidence chips, per-server dots, "Needs review", bulk publish.
5. **Job details:** per-server "Markers written × N / reused / needs review / skipped (reason)".
6. **Setup Health:** plugin missing/outdated, Plex Pass missing, Plex marker tag absent, Plex detection overwrite risk.

All non-obvious controls get ⓘ tooltips.

## 11. Risks and open items

1. **TheIntroDB terms** — used without authorization (owner decision); per-user keys; must degrade gracefully.
2. **Plex DB writes are unsupported by Plex** — opt-in with confirmation; schema changes in future PMS could break
   them; detect unknown schema and stop writing.
3. **Plex client display** — proven at the API (served XML identical to native markers), not observed in a Plex app
   (Plex Web requires plex.tv login). Verify on a real client in phase 1.
4. **Plex Pass for viewers** — non-Pass viewers never see skip buttons; state it in the UI.
5. **Emby catalog acceptance** — not guaranteed; manual install fallback.
6. **Multi-version items** — Jellyfin alternate versions and Plex shared markers need a lab test in phase 1.
7. **Credits truth is subjective** (epilogues, post-credit scenes) — the labelled set encodes the "credit roll" rule.
8. **Jellyfin 12.0 plugin catalog install** of the current 10.11-only Bridge manifest is untested (manual load works).

## 13. Revision 2 (2026-09-13) — answers to review questions

### 13.1 Plex: is there really no non-database route?
Plex has no plugin system (removed years ago). Every other route was tried:

| Route | Result | Evidence |
|---|---|---|
| REST `…/marker` | Bookmarks only: every type 400, edit/delete 404, bookmark→intro PUT ignored | (lab) |
| Hidden routes | PMS binary has only `/marker`, `/marker/:markerID`; Plex Web 4.160 only reads markers | binary strings + JS bundles |
| Custom Metadata Providers (Dec 2025) | Spec has no marker/media/part fields | developer.plex.tv |
| Cloud credits lookup redirect | PMS asks `tv.plex.provider.metadata` `/markers?hash=<media_parts.hash>&type=credits` (credits only). Hidden pref `MetadataProviderUrl` set to a lab proxy: **zero requests reached the proxy**, even on refresh/forced credits → not honoured on 1.43.4 | (lab) `evidence/plex-provider-redirect/` |
| Chapter names | Never converted to markers | Plex staff + strings |
| Plex database | Works (see §3.1) | (lab) |

PR #241's design also used a DB write. Its claim that DB writes help **non-Pass** users is wrong:
**(lab) an unclaimed / no-Pass server serves no markers at all even when they are in its DB, and hides marker
settings.** So Plex publishing only makes sense on Plex Pass servers. Viewers also need Pass or Plex Home (docs).
DB access: the app already mounts Plex's data folder for previews; the DB is in the same tree
(`Plug-in Support/Databases`). Refuse writes when the DB is on a network filesystem (SQLite locking).
Plex read-only mode (Plex markers as evidence, published to Jellyfin/Emby only) stays available.

### 13.2 Integration with previews — separate job type, shared plumbing (AGREED)
Intro & Credits is its own job type: own queue, schedules, priority, pause/cancel, retries. It reuses triggers,
owner/path resolution, the process-wide frame cache, job storage/list UI and per-server result rows.
- **Webhook:** preview job runs unchanged; an Intro & Credits job is enqueued with a short debounce (minutes) and
  grouped per season folder, so a batch of episodes → one job per season. Shown on the dashboard linked under the
  preview job that triggered it. Gets first call on the online lookup quota.
- **Frame reuse:** `FrameCache` is a process-wide singleton keyed by canonical path + mtime, TTL 60 min, with a per-path
  generation lock (verified in `processing/frame_cache.py`). Credit-text detection reads cached frames when present
  (320px = 640px results on 7/7 movies); otherwise samples 320px frames itself.
- **Backfill:** "Start job → Intro & Credits" for chosen libraries or a low-priority schedule; never touches previews;
  resumable via `markers.db`; uses leftover online quota, local detection otherwise.
- **Schedules:** independent from preview schedules; each skips files already done.
- **Manual edits:** no job; save, lock, publish immediately.
- Why not "same jobs": less control, and markers would have to live inside the freshly unified dispatcher (#243)
  whose per-file GPU shape doesn't fit season batching / rate-limited lookups. (An earlier claim that separate jobs
  lose frame reuse was wrong — the cache is shared.)

### 13.2b Plex database must be local to the app
Plex's library DB is WAL mode (checked on prod). SQLite: "All processes using a database must be on the same host
computer; WAL does not work over a network filesystem" (sqlite.org/wal.html). Preview files over NFS/SMB are fine; the
DB is not. The Plex publisher checks the filesystem type of the DB directory and disables itself with a clear message
when it's a network mount (NFS/SMB/CIFS, Docker Desktop shares). Prod (`plex` host) is local ext4 → supported.
"Re-applies" = when Plex force-re-detects an item it replaces our markers; reconcile notices and writes ours back.

### 13.3 Online coverage on the real library
Random 200 TV episodes + 120 movies from prod Plex (`evidence/coverage/`):

| Source | TV | Movies |

### 13.6 Per-server settings (supersedes §7.1, §7.2 server rows, §8 per-server line)
A file is detected once (global); what each server receives is that server's own config. Several servers of one type
are normal (two Plex, a Jellyfin, an Emby).

**UI.** Servers page → server card → **Edit** → new tab **Intro & Credits** (after "Webhook & Scanner"):
- Switch "Send intro & credits markers to this server".
- Libraries: that server's libraries with checkboxes (sports-type libraries unchecked by default).
- Status block per type: Plex = write method (database), Plex Pass state, DB location + local-disk check, Plex's own
  detection on/off, "If Plex re-detects: put ours back / keep Plex's". Jellyfin/Emby = plugin name, installed version
  vs required, Install/Update button, which marker types the server can show.
- Plex only: enabling asks the database-write confirmation (once per Plex server; stores `db_write_confirmed_at`).

**Settings → Intro & Credits** holds only detection (shared by all servers): detect Intros/Credits/Recaps, publish
rule, never overwrite my edits, ordered sources (chapters, TheIntroDB + key + quota, IntroDB.app, SkipDB, season audio,
credit text, markers already on servers).

**Config.**
```json
"markers": {                       // root, shared detection
  "detect": {"intro": true, "credits": true, "recap": false},
  "publish_when": "high",          // "high" = chapters or two sources agree; "medium" = one strong source
  "respect_locks": true,
  "sources": [
    {"id": "chapters", "enabled": true},
    {"id": "theintrodb", "enabled": false, "api_key": ""},
    {"id": "introdb", "enabled": true},
    {"id": "skipdb", "enabled": true},
    {"id": "season_audio", "enabled": true},
    {"id": "credits_text", "enabled": true},
    {"id": "server_markers", "enabled": true}
  ]
}
"media_servers": [{ "...": "...",
  "markers": {
    "enabled": false,
    "library_ids": null,             // null = all libraries except sports-type; else explicit list
    "plex": {"db_write_confirmed_at": null, "on_plex_redetect": "restore"}   // Plex servers only
  }
}]
```
- Job fan-out: owners of a file = `find_owning_servers`; publish to owners with `markers.enabled` and the item's library
  in `library_ids`. `publish_state` is keyed per `server_id`, so two Plex servers are tracked independently.
- Plex DB path per server comes from that server's `output.plex_config_folder`; the local-disk check runs per server
  (one Plex local → writable, another remote → read-only with message).
- Detection runs when **any** server that owns the file has markers enabled; nothing is detected for files no enabled
  server owns.

### 13.7 Detection settings (tested 2026-09-13)
Research (ffmpeg/chromaprint docs, intro-skipper, jellyfin-plugin-media-analyzer, Plex/Emby behaviour write-ups)
then measured on this library. Evidence scripts: `evidence/eval/sweep_intro.py`, `snap_test.py`, `fp_variants.py`,
`evidence/credits/`.

**Intro (season audio).**
- Fingerprint variants on the 118-episode chapter-truth set (useful / wrong / missed):
  chromaprint alg1 stereo `-ac 2` **91 / 13 / 14** (chosen) · alg4 stereo 87 / 11 / 20 · alg0 stereo 86 / 15 / 17 ·
  front-channel mono 80 / 20 / 18 · alg2 stereo: result below. Algorithm 3 is unusable for timing: chromaprint's
  Test4 config sets `set_remove_silence(true)` (fingerprinter_configuration.cpp), which drops leading silence and
  shifts every timestamp.
- Matcher parameter sweep (tuned on half, checked on the other half): v3 parameters (§5.2) were already best on the
  held-out half; no change.
- End snapping to silence: tested, made results worse → not used. Chapter snap (±3 s) stays when chapters exist.
- Cost ~2 s CPU per episode; fingerprints cached per file.

**Credits (on-screen text).** See results block below (filled after the 80-file run).
- Frames: reuse preview frames from `FrameCache` when fresh (user's interval 6 s, app default 10 s). Otherwise one
  decode pass over the tail: NVDEC `fps=0.5,scale_cuda=320:180` ≈ 50 s for 15 min of 1080p on a loaded box; keyframes
  only (`-skip_frame nokey -copyts`, correct timestamps) 26.5 s CPU / 13.8 s CUDA. Per-frame exact seeks are slowest
  (150–270 s) → never.
- Text detector: RapidOCR detection only (no recognition) at the frame's own size (`det_limit_side_len=320,
  det_limit_type="max"`): same hits as default upscaling (19/19, 0 false), far cheaper.
- **CPU vs GPU for text detection (measured on storage, P5000, 13 frames × 10):** ONNX Runtime CUDA 7.7 ms/frame;
  CPU with `intra_op_num_threads=2` 23 ms/frame; identical box counts. Earlier 119 ms/frame figures were uncapped
  threads fighting other jobs on a loaded host. GPU needs `onnxruntime-gpu` + CUDA/cuDNN wheels = **+2.8 GB** image
  (image today 2.59 GB) and Pascal needs CUDA 12 + cuDNN ≤ 9.5 (cuDNN 9.26 fails `CUDNN_BACKEND_API_FAILED`); CPU
  runtime is ≈ +300 MB (onnxruntime 62 MB, rapidocr 16 MB, opencv-headless ≈ 150 MB, numpy 59 MB, shapely/pyclipper
  15 MB; measured in the lab venv). A 15-min tail at 6 s = 150 frames ≈ 3.5 s CPU. **Recommendation (owner to confirm): decode on
  GPU via the existing ffmpeg hwaccel; text detection on CPU capped at 2 threads.**
- **Resource rule (owner, 2026-09-13: research jobs "killing storage"):** Intro & Credits jobs run 1 worker by default,
  ORT 2 threads, ffmpeg `-threads 2`, lowest priority; never parallel per-frame seeks. Audio fingerprinting is
  CPU-only (no GPU chromaprint) but ~2 s/episode — 2 at a time max.
- Measured GPU sampling cost: keyframes over a movie's last 15 min + 100 s full decode at 1 fps + GPU text detection
  = 8–13 s per movie, ~1 CPU core.
