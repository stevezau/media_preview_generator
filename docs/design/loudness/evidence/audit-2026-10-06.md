The queue correction retains one initial job for a selected file list rather
than creating a visible job for every 500 files. The exact selection and retry

rewrite or broadcast the full selection. The independent predecessor-ID bound

## Deletion ordering correction and final candidate

later import reusing the same, temporarily absent filename. The correction uses
immutable creation timestamps from SQLite, because retry heads change their
in-memory timestamps for display ordering. Original heads retain their import
notices; retry attempts do not create new import events. Batch fire times or

The admission correction counts active jobs by kind and captured admission
priority, using open compatible worker capacity. Blocked jobs do not hold global
slots, and an eligible different kind can pass them in the admission queue.
Higher-priority work can enter ahead of lower-priority scans so it can reach the
dispatcher's file-level priority queue. An ordinary per-kind ceiling leaves
space for another kind, with an explicit exception for work strictly higher in

## Application hardening after the chapter recheck

The follow-up application changes described here are local implementation and
test evidence. They have not yet been deployed or proved against the live
malformed source at the time of this entry. The earlier source/image deployment
records remain the production baseline.

A further read at 22:54 UTC confirmed that the separate 12-chapter publication
conflict had already resolved under the deployed code's ordinary retry policy:
the original head and its retry completed at 22:46:47 with no error, and the
latest file result reported all 12 chapters ready while reusing the existing
BIF. This is evidence that the strict consistency refusal can recover normally,
not proof that its original changed field was harmless.

Chapter processing now inspects bounded Matroska index data in a disposable
process before seeking. An inspection timeout or unclassified format is not
treated as proof of corruption. When a damaged index is proved, or a chapter
seek stalls, recovery can use an existing BIF only if the app's journal binds
it to the exact current source fingerprint. The BIF index and JPEG are
validated; the chosen frame must be within that chapter and within five seconds
after its start. Its original timestamp, dimensions and recovery cause are
saved in the chapter manifest, and the result reports the lower-resolution
recovery. A native Plex BIF without a matching journal cannot establish this
provenance. Neither this path nor its diagnostics modify the original media.

The first stalled or corrupt seek switches remaining work to the verified-BIF
path rather than repeating an expensive failing seek for every chapter. Existing
completed images remain reusable. With no safe recovery frame, an explicit
failure remains; proven corruption does not automatically retry the same source.
Chapter FFmpeg attempts have an active-time deadline that excludes manual pause.
Termination waits are bounded for this path; a process still held in kernel I/O
is reported as pending cleanup and reaped separately rather than falsely claimed
to have exited. Ordinary preview extraction keeps its existing policy.

Publication retains the original all-or-nothing SQLite snapshot check. The
application permits one fresh registration attempt only when the sole difference
is `source_updated_at`, with the source fingerprint verified around the work.
Changed image references, chapter timings, row identities or media identities
remain conflicts. Errors name changed fields without exposing their values.
Plex API read-back is still required before chapter completion is reported.

The independent real-SQLite publication matrix passed nine cases: timestamp-only
refresh and exact API read-back, changed references/timing/hash/size refusals,
source replacement before retry, a second concurrent timestamp change, absence
of the required source verifier, and stale API visibility after a committed
write. The existing publisher suite passed 58 tests. Separate deadline tests
exercise noisy output, pause accounting, cancellation and pending-process
reaping; recovery tests cover invalid indexes, source identity, BIF provenance,
chapter timing bounds and rejection of excessive resized image dimensions.
These checks do not yet constitute a live deployment result.

The Jobs page adds a historical chapter-warning count and filter, without
changing the default unfinished-job selection. Hidden attempts are excluded;
typed chapter counts take precedence over legacy publisher summaries. The
notice describes jobs that ended with issues, not a current broken-file count.
Terminal details expose the existing full-selection **Re-run job** action;
the existing **Retry now** action remains limited to pending attempts. This
preserves partial scrubber success and old warning history without presenting
an exhausted chapter chain as wholly resolved. The focused static UI detector

The packaged synthetic-media proof caught an additional compatibility issue:
FFmpeg 8.1.2 identifies its demuxer as `in#0/matroska,webm`, which the original
